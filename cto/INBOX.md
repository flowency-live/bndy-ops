# CTO INBOX

**Every scheduled task writes here. No task writes to the chat.**

This file is the only place an unattended run raises something. Jason reads this file when he chooses. He does not read task chats.

## Rules for a run

1. Append. Never edit another run's line. Never delete a line.
2. One line per item. Use the format below.
3. If you have nothing to raise, write nothing. An empty run does not append.
4. Do not append an item that an existing rule already answers. That is work, not an item.
5. Do not append the same item twice. Search this file for the fingerprint first.

## Format

```
| DATE | SOURCE | KIND | FINGERPRINT | ONE LINE | EVIDENCE |
```

- **KIND** is one of: `DEFECT` (tool or backend fault) · `RULE` (a rule is wrong, missing or unreachable) · `DATA` (a record needs correcting) · `BLOCKED` (the run could not finish) · `DECISION` (needs Jason).
- **FINGERPRINT** is a short stable slug. It is how a later run knows the item is already here. Example: `create-artist-500-namevariants`.
- **ONE LINE** is 25 words maximum.
- **EVIDENCE** is a file path, a UUID, or a URL. Never a description.

## Triage

Jason or the CTO agent moves items out of here.

- `DECISION` → `DECISIONS.md`, with three options and a recommendation.
- `DEFECT` / `RULE` / `DATA` → `WORK-ITEMS.md`.
- Done → strike the line. Keep it. Never delete.
